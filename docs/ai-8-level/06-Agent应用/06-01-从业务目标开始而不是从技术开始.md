# 6-01 从业务目标开始而不是从技术开始

欢迎回到 AI 使用能力系列。从这一级开始，我们进入第 6 级——Agent 应用。

前五个级别我们解决了"怎么对话""怎么处理文件""怎么编排任务""怎么自动化"的问题。这一级要更进一步：怎么建设一个完整的、可交付的业务 Agent 应用。

## Agent 应用和自动化的区别

先澄清一个概念。第 5 级讲的自动化是一个流程——数据进来，处理完，结果出去。它是线性的、可预测的。

Agent 应用不同。它需要和用户对话，需要根据对话内容决定下一步做什么，需要检索知识来回答问题，需要调用工具来执行操作，需要在不确定情况下做出判断。

换句话说，自动化是"按流程执行"，Agent 是"在边界内自主决策"。

但"自主"不等于"随意"。一个好的 Agent 应用的自主程度是经过精心设计的——它知道什么可以自己决定，什么需要问用户确认，什么必须转人工。

## 从业务目标开始，不是从技术开始

建设 Agent 应用的第一个错误是从技术开始："我们要用什么模型？用什么框架？用什么知识库？"

正确的问题顺序是：

谁在使用这个 Agent？——目标用户是谁？

用户要完成什么任务？——不是"聊天"，而是具体的业务任务。

Agent 可以做什么、不可以做什么？——能力边界在哪里？

成功指标是什么？——怎么判断 Agent 做得好不好？

出了错谁负责？——人工责任在哪里？

这些问题回答清楚了，技术选型才有意义。否则你就是在拿着锤子找钉子。

## 角色卡：定义 Agent 的身份

角色卡是 Agent 应用的"身份证"。它定义了：

Agent 名称——叫什么？

服务对象——为谁服务？

业务结果——要达成什么业务目标？

可以回答——哪些问题可以回答？依据什么？

可以行动——哪些操作可以执行？权限是什么？

必须确认——哪些操作需要用户确认？

必须拒绝——哪些请求必须拒绝？

必须转人工——哪些情况必须转人工？

禁止动作——哪些操作绝对不能做？

失败表现——失败时怎么表现？

责任人——谁对 Agent 的行为负责？

角色卡不是技术文档，而是业务文档。它告诉业务方：这个 Agent 能做什么、不能做什么、出了问题找谁。

## 一个角色卡示例

假设你要建设一个"售后支持 Agent"。

```markdown
# 角色卡：售后支持助手

Agent 名称：售后支持助手 v1.0.0

服务对象：已通过认证的产品用户

业务结果：在不越权、不猜测的前提下回答公开售后问题、查询本人订单、生成低风险案例草稿或完整转人工

可以回答：当前时间有效、产品匹配、权限为 PUBLIC 的知识；必须引用 doc_id@version

可以行动：查询认证用户本人的沙箱订单；当前轮明确确认后创建沙箱案例草稿；创建人工接管单

必须确认：创建案例草稿前必须展示摘要并取得当前轮明确"确认创建"

必须拒绝：系统提示、密钥、内部知识、其他客户订单、批量客户数据和绕过权限请求

必须转人工：退款、改址、取消、补偿、投诉升级、人身安全、敏感身份信息、资料冲突、权限不足、工具结果未知

禁止动作：实际退款、订单修改、订单取消、补偿决定、外部通知和任何生产写入

失败表现：明确说明当前无法核实，不猜测；保留已知上下文，给接管编号或建议稍后重试

责任人：产品负责人决定边界；技术负责人维护版本；人工坐席承担最终高风险决定
```

你看，角色卡清楚地定义了 Agent 的能力边界。它不是"什么都能做"，而是"在明确边界内做事"。

## 架构画布：设计 Agent 的组合方案

角色卡定义了"做什么"，架构画布定义了"怎么做"。

架构画布包含九个区域：

用户与身份——谁在使用？可信身份从哪里来？

入口与策略——哪些请求在模型前就必须拦截或脱敏？

知识——如何按产品、有效期、权限过滤？如何引用和无答案？

工具——工具输入、输出、副作用、权限、超时、幂等是什么？

编排——什么时候答知识，什么时候查工具，什么时候确认或接管？

状态与记忆——保存什么、多久、谁可见、怎样删除？

输出门禁——如何检查引用、权限、敏感信息和高风险动作？

观测与评测——如何关联会话、检索、工具、接管、版本、成本和样本？

运营——谁监控、回滚、更新知识和处理反馈？

架构画布不是一次性填完的，而是随着项目推进逐步完善。但它帮你系统地思考 Agent 的每个组成部分。

## 第 6 级的学习目标

第 6 级要让你掌握四个能力：

第一，明确 Agent 的用户、业务目标、任务边界和人工责任，不从聊天界面反推需求。

第二，设计模型、知识、工具、状态、记忆、反馈和治理的组合方案。

第三，建立包含正常、边界、失败和攻击样本的评测集，并用固定指标比较版本。

第四，处理知识引用、工具越权、提示注入、重复执行和不可观测失败。

这四个能力不是理论，而是实操。你会在沙箱环境中建设一个完整的 Agent MVP，包含知识检索、工具调用、状态管理和评测。
