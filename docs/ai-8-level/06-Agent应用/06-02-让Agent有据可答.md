# 6-02 知识检索——让 Agent 有据可答

欢迎回来。上一集我们学了从业务目标开始和角色卡设计。今天我们聊知识检索——怎么让 Agent 有据可答，同时避免过期和越权。

## 为什么需要知识检索

大多数业务 Agent 都需要知识支持。用户问一个问题，Agent 需要从知识库中找到相关信息，然后基于这些信息来回答。

这就是所谓的 RAG——检索增强生成。但今天我不讲技术细节，我讲几个关键的设计原则。

## 知识必须有版本和有效期

一条知识可能在上个季度是有效的，但这个季度已经废止了。Agent 必须能区分当前有效和已过期的知识，不能因为过期知识的相似度更高就使用它。

比如你有一份产品手册，2025 年版说"按连接键 10 秒进入配网"，但 2026 年版说"按连接键 3 秒进入配网，10 秒会进入恢复模式"。如果用户问"怎么配网"，Agent 必须使用 2026 年版，不能用 2025 年版。

知识条目应该包含：doc_id、version、valid_from、valid_to。检索时必须过滤：valid_from ≤ 当前时间 ≤ valid_to。

## 知识必须有权限

有些知识是公开的，所有人都可以知道。有些知识是内部-only，只有特定角色才能访问。Agent 必须根据用户的权限来过滤知识，不能把受限知识回答给没有权限的用户。

比如你有一份内部诊断手册，只有人工支持角色可以访问。如果用户问"内部诊断入口是什么"，Agent 不能说"根据内部手册，诊断入口是..."。它应该说"我没有找到相关信息"，或者转人工。

知识条目应该包含：permission（PUBLIC、SUPPORT_INTERNAL、SUPERVISOR_ONLY）。检索时必须过滤：permission = PUBLIC（对于普通用户）。

## 回答必须引用来源

Agent 的每一个事实性回答都应该标注它引用了哪条知识、哪个版本。这样用户可以去核实，你也可以在出错时追溯原因。

比如用户问"CS-1 怎么配网"，Agent 回答："首次配网：通电后按连接键 3 秒，蓝灯慢闪时，在 App 选择'添加 CS-1'；不要按 10 秒，10 秒会进入恢复模式。（来源：K01@2.0）"

引用格式：doc_id@version。这样用户知道这个答案来自哪个文档的哪个版本。

## 无答案时诚实说明

如果知识库中没有相关信息，Agent 应该说"我没有找到相关信息"，而不是用训练数据中的常识来编造一个答案。

比如用户问一个非常偏门的问题，知识库里没有相关条目。Agent 不应该猜，而应该说"我没有找到相关信息，建议联系人工支持"。

无答案的表现是 Agent 可靠性的重要指标。一个总是"有答案"的 Agent 可能是在编造，一个敢于说"不知道"的 Agent 反而更可信。

## 检索前的过滤

检索不是"把所有知识都扔给 AI"。检索前必须同时过滤产品、有效期和权限。

比如用户问"CS-1 怎么配网"，检索时应该过滤：

产品：CS-1
有效期：当前时间在 valid_from 和 valid_to 之间
权限：PUBLIC

过滤后，只有符合条件的知识条目进入候选。这样可以避免：

- 返回 CS-2 的配网方法（产品不匹配）
- 返回 2025 年的旧流程（已过期）
- 返回内部诊断手册（权限不足）

## 一个知识检索案例

假设知识库中有 20 条知识条目，用户问"CS-1 第一次怎么配网"。

检索流程：

第一步，过滤产品。只保留 products 包含 "CS-1" 的条目。

第二步，过滤有效期。只保留 valid_from ≤ 当前时间 ≤ valid_to 的条目。

第三步，过滤权限。只保留 permission = PUBLIC 的条目。

第四步，相似度排序。按查询和内容的相似度排序，取 top 3。

第五步，返回结果。返回 doc_id、version、content、score。

假设过滤后剩下 3 条：

K01@2.0：首次配网：通电后按连接键 3 秒...（score: 0.98）
K03@1.3：指示灯：蓝色慢闪表示等待配网...（score: 0.85）
K04@1.0：安全重启：短按电源键一次...（score: 0.72）

Agent 基于 K01@2.0 回答用户问题，并引用来源。
