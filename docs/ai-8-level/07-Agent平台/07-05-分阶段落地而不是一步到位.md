欢迎回来，这是第 7 级的最后一集。前四集我们学了平台认知、六层架构、身份链路和发布门禁。今天我们聊建设路线。

## 平台建设不能一步到位

很多企业的想法是：买一个平台产品，把所有 Agent 都接进去，问题就解决了。

但现实是：平台建设需要分阶段，先解决高复用、高风险的公共能力，再逐步扩展。

## 90 天：证明平台价值

前 90 天的目标是：至少有两个不同业务的 Agent 接入同一公共能力，证明平台的价值。

比如：客服 Agent 和内部知识助手都接入统一的模型网关，证明模型接入的复用价值。

或者：客服 Agent 和研发 Agent 都接入统一的身份链路，证明身份管理的复用价值。

90 天不追求全面，只追求"证明公共能力有用"。

## 半年：扩展到第三个业务

半年的目标是：扩展到第三个业务，建立完整的评测、观测和成本管控。

比如：三个 Agent 都接入统一的模型网关、知识管理、身份链路、日志追踪和成本核算。

半年追求"三个业务证明公共能力的稳定性和可扩展性"。

## 一年：建立运营机制

一年的目标是：建立运营机制、组织能力和供应商退出演练。

运营机制——谁监控、谁回滚、谁更新知识、谁处理反馈？

组织能力——培训、支持、申诉机制是否到位？

供应商退出——如果三年后需要更换供应商，你需要导出什么数据？迁移什么知识？重新对接什么接口？

一年追求"平台可以持续运营，不依赖某个供应商或个人"。

## 路线图的单位

路线图的单位不是"采购了什么模块"，而是"可验证的业务接入和控制能力"。

比如：

错误里程碑："Q1 上线模型网关"。

正确里程碑："Q1 客服和知识助手接入统一模型网关，模型切换时间从 2 天缩短到 2 小时"。

正确的里程碑有业务证据，错误的里程碑只有采购动作。

## 第 7 级总结

到这里，第 7 级就结束了。回顾一下你学到了什么：

为什么需要平台——避免烟囱式建设，识别公共能力。

六层架构——模型、数据与知识、工具、编排、应用、治理。

身份链路——从用户到工具的可追溯授权。

发布门禁——用证据控制变更，高风险样本单独判定。

建设路线——90 天证明价值，半年扩展，一年建立运营机制。

## 下一步

第 7 级的终点是：你能设计公共能力、稳定契约、治理机制、运营指标和建设路径。

如果你已经做到了，可以进入第 8 级——企业 AI 赋能。在那里，你会学到怎么从企业经营目标出发，决定哪些业务场景值得用 AI 重构。
