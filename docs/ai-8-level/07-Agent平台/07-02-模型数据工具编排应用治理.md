## 六层架构

企业 Agent 平台通常包含六层：

第一层，模型层。提供统一的模型接入、路由、限流和降级。业务团队不需要各自对接不同的模型供应商。模型切换时，上层的知识和应用不应该受影响。

第二层，数据与知识层。管理知识的所有权、索引隔离、权限过滤、版本血缘和删除传播。知识不是无主缓存——它有所有者、有权限、有有效期。

第三层，工具层。提供工具注册、身份传递、风险分级、审批和紧急停用。工具调用必须知道"谁在调用、替谁调用、重复一次会怎样"。

第四层，编排层。提供流程编排、状态管理和异常处理。

第五层，应用层。各业务团队的 Agent 应用。

第六层，治理层。贯穿所有层的身份权限、审计、评测、观测和成本管理。

治理不是第七个收尾盒子，它要穿过每一层。每条数据流都要带身份、数据等级、版本和追踪标识。

## 模型层

模型层的核心是：与具体模型供应商解耦的统一接入。

它提供：模型网关、路由策略、限流降级、供应商切换。

业务团队不需要知道底层用的是哪个模型。他们只需要调用统一的接口，平台负责路由到合适的模型。

模型切换时，上层的知识和应用不应该受影响。这就是"解耦"的价值。

## 数据与知识层

数据与知识层的核心是：知识的所有权和生命周期管理。

它提供：知识接入、索引隔离、权限过滤、版本管理、删除传播。

知识不是无主缓存。每条知识都有所有者、有权限、有有效期。当知识更新或删除时，必须确保索引中的副本也同步更新或删除。

不同业务的知识不能混入同一个无隔离索引。客服的知识、制度的知识、代码的知识——它们有不同的权限和访问规则，必须隔离。

## 工具层

工具层的核心是：工具注册和执行控制。

它提供：工具注册、身份传递、风险分级、审批、幂等、紧急停用。

每个工具都有明确的输入、输出、副作用、权限和失败处理方式。工具调用必须知道"谁在调用、替谁调用、重复一次会怎样"。

高风险工具（如退款、改址）必须有人工审批。工具侧保留最终授权，平台不能用一个万能账号代替用户身份。

## 编排层

编排层的核心是：流程编排和状态管理。

它提供：流程定义、状态保存、异常处理、重试降级。

编排层把多个工具和知识调用组合成一个完整的任务流程。它负责保存中间状态、处理异常、在失败时恢复。

## 应用层

应用层是各业务团队的 Agent 应用。

每个应用有自己的业务逻辑、用户界面和特定规则。但它们共享平台提供的模型、知识、工具和治理能力。

应用团队不需要从零建设所有能力。他们只需要关注自己的业务逻辑，其他能力由平台提供。

## 治理层

治理层贯穿所有层，提供：身份权限、审计、评测、观测、成本管理。

身份权限——谁有权做什么？权限如何传播和撤销？

审计——出了问题能否还原所用版本和来源？

评测——如何衡量 Agent 的表现？如何比较版本？

观测——如何监控业务、模型、工具、成本和安全信号？

成本——如何归属成本？如何设置配额和预算？

治理层不是独立的第七层，而是穿过每一层的控制面。
