欢迎回来。上一集我们建立了聊天和工作区的基本认知。今天我们聊工作区的第一个核心技能：上下文组织。

## 为什么不能把所有东西塞进一个提示框

在聊天中，你习惯把所有内容粘贴到一个提示框里。但在工作区中，这种方式行不通。

工作区通常有多个文件，每个文件的角色不同。有的文件是稳定的背景信息，很少变化；有的文件是当前任务的输入，用完就可以归档；有的文件是规则，定义了 AI 能做什么、不能做什么。

如果你把所有文件混在一起，AI 就不知道：哪些信息是稳定的、可以长期参考的；哪些信息是当前的、可能过期的；哪些是规则、必须遵守的。

这种混乱会导致错误。比如 AI 可能会把历史信息当成当前决策依据，或者把规则文件当成可以修改的内容。

## 五类上下文

我把工作区的上下文分成五类：

### 第一类：入口说明

入口说明是工作区的导航地图。它告诉 AI：这个工作区是做什么的、文件放在哪里、哪些能改哪些不能改、最终要交付什么。

入口说明应该精简，只做路由和关键规则，不要把全部内容都堆进去。

一个好的入口说明包含：项目目标、目录路由、执行边界、验收要求。

比如：

```markdown
# 项目目标

根据当前项目材料，在指定路径完成《活动执行方案》和《验收报告》。

## 目录路由

- background/：稳定背景，只读。
- conventions/：执行规则，修改前必须确认。
- materials/：当前输入材料，只读。
- output/：唯一可写目录，最终交付物。

## 执行边界

- 允许读取：background/、conventions/、materials/
- 允许修改：output/
- 必须确认：涉及敏感信息的操作
- 禁止：读取工作区外文件、修改原始材料

## 验收要求

- 最终交付：output/event-plan.md、output/acceptance-report.md
- 必须运行：格式检查、敏感信息检查
- 必须报告：材料不一致、信息缺失
```

入口说明不是百科全书。它只告诉 AI"去哪里找什么"和"什么能做什么不能做"，不存放具体的业务内容。

### 第二类：背景资料

背景资料是稳定的、不常变的信息。比如组织介绍、受众描述、项目背景。

这些文件是只读的，AI 可以参考但不能修改。它们提供理解任务的上下文，但不是任务的直接输入。

比如 `background/organization.md` 描述组织架构，`background/audience.md` 描述目标受众。这些信息在多次任务中都可以复用。

### 第三类：规则

规则定义了 AI 的行为边界。比如写作规范、隐私要求、操作限制。

规则也是只读的，修改前必须经过人工确认。它们不是建议，而是必须遵守的约束。

比如 `conventions/writing.md` 定义写作格式，`conventions/privacy.md` 定义隐私和权限规则。

规则的重要性在于：当 AI 遇到不确定的情况时，它应该回到规则文件找答案，而不是自己猜。

### 第四类：当前材料

当前材料是这次任务要用到的输入。比如一份会议纪要、一个旧方案、一组数据。

这些文件也是只读的——AI 应该基于它们来工作，但不应该修改它们。

比如 `materials/meeting-notes.md` 是当前会议纪要，`materials/old-plan.md` 是历史方案。AI 读取这些材料，提取信息，生成新的输出。

当前材料和背景资料的区别在于：背景资料是稳定的、多次复用的；当前材料是一次性的、任务特定的。

### 第五类：输出目录

输出目录是唯一允许 AI 写入的地方。所有 AI 生成的内容都应该放在这里。

比如 `output/event-plan.md` 是活动执行方案，`output/acceptance-report.md` 是验收报告。

输出目录的设计原则是：所有变更都在这里发生，所有审查都在这里进行。原始材料不受影响。

## 为什么要分这么细

你可能会觉得这种分类太繁琐。为什么要分五个目录？直接把所有文件放在一起不行吗？

原因是：分类错误会变成权限错误。

如果你把当前材料和稳定背景混在一起，AI 可能会把历史信息当成当前决策依据。

如果你把规则放在可写目录里，AI 可能会在修改文件时不小心改了规则。

如果你没有明确的输出目录，AI 可能会在原始材料上直接修改，导致无法恢复。

分类的目的不是美观，而是控制。它让 AI 知道每类文件的角色，从而做出正确的操作。

## 一个实操案例

假设你的工作区结构是这样的：

```text
workspace-demo/
├── README.md                         # 入口说明
├── task.md                           # 任务书
├── background/
│   ├── organization.md              # 组织背景
│   └── audience.md                  # 受众描述
├── conventions/
│   ├── writing.md                   # 写作规则
│   └── privacy.md                   # 隐私规则
├── materials/
│   ├── meeting-notes.md             # 当前会议纪要
│   └── old-plan.md                  # 历史方案
└── output/
    └── event-plan.md                # 活动执行方案（AI 生成）
```

当你让 AI"根据会议纪要更新活动方案"时，它会：

1. 读取 README.md 了解工作区结构和边界
2. 读取 background/ 了解组织和受众
3. 读取 conventions/ 了解写作和隐私规则
4. 读取 materials/meeting-notes.md 和 old-plan.md 获取输入
5. 在 output/ 中生成或修改 event-plan.md

每一步都有明确的文件角色和权限。AI 知道哪些能读、哪些能改、哪些必须遵守。
